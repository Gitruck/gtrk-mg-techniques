# candle-chart · K 线图动画

四个动作，一条时间线：

| 动作 | 画面 | 用在什么时候 |
|---|---|---|
| **生长** | 蜡烛从左到右逐根长出：每根从开盘价向收盘价与两端影线展开；成交量柱同步升起 | 「这段时间它是这么走的」——口播在讲趋势、讲过程 |
| **描均线** | 均线笔尖跟着最新长出的那根推进；或等蜡烛长完再单独描一遍 | 讲「趋势」「拐头」「金叉死叉」时把平滑线拎出来 |
| **点位标注** | 一根蜡烛上落一个点，引线拉出标签（最高 / 最低 / 收盘 / 任意价位） | 「最高冲到 52.28」「那一周收在全年最低」 |
| **价位线 / 区间** | 一条水平虚线从左划到右、右端挂价签；或一段区间整片亮起 | 「前高压力」「34 块是支撑」「这三个月的回撤」 |

## 分工：你决定内容与节奏，脚本只做机械活

**你（agent）负责**：画哪段行情（数据、截取、要不要合并成周线）、用哪种配色约定、强调哪根哪价、价位线画在哪、每一步落在口播的哪一秒、标签写什么。
**脚本负责**：读数据与校验 OHLC、合并周期、算均线、定纵轴范围与整数刻度、排蜡烛 / 量柱 / 均线 / 标注的几何、给标注留头顶空间、查标签互相避让、发射时间线、自检。

这是**技法**不是模板：脚本里没有行情、没有标的名、没有栏目色板。同一份脚本给不同数据产的颗粒应当完全不一样——差别在你写的 spec。

## 工作流

### 1. 拿数据

- CSV（表头 `date,open,high,low,close[,volume]`，也认 `d/o/h/l/c/v` 与「日期 / 开盘 / 最高 / 最低 / 收盘 / 成交量」），或 spec 里内联 `data`。
- 只用你有权使用的数据；画面上注明来源与口径（复权与否、时区）——放在 `header.sub` 或旁边的文案卡里。
- 一屏放多少根：1920 宽的缺省版面 **≤ 200 根**看得清（每根 ≥ 7px）；脚本在每根 < 2.5px 时拒绝。
  多了就 `aggregate`（5 = 日线并周线）或 `slice` 截取口播讲的那一段。

### 2. 先跑一遍拿读数

```bash
python scripts/candle_chart.py <spec.json> --out <落点.html>
```

stdout 的 `extremes` 给出这段数据的最高价、最低价、最高 / 最低收盘、首开末收（各带日期）。
**标签里的数从这里取，别凭印象写**——标签里出现与价位同精度的小数却不等于那根的实际价位，脚本会拒绝。

### 3. 按口播定节奏

拿句级时码（`transcript.json` 的 `st/ed`）按字数内插估某个词的时刻，减去颗粒起点 `track_st`。经验值：

- **生长**压在讲「走势」的那句上：`grow.start` = 开始讲这段的时刻，`grow.end` = 讲完「先涨后跌」这类概括的时刻。
  3–7 s 合适；太快看不清形态，太慢观众会等。
- **均线**：讲趋势时用缺省的跟随（`ma: [5, 20]`）；要单独强调「均线拐头」就给 `ma.at`，等蜡烛长完再描。
- **点位 / 区间 / 价位线**：每个 `t` = 口播说到那个价或那段的时刻（−0.2 s 提前量）。每个动作之间 ≥ 1 s，一个 beat 不超过 4 个。
- 全部动作结束后至少留 0.3 s 驻留（脚本会拦）；终态是一张完整的图，静止即合法（铁律 7）。

### 4. 写 spec

字段全表见 `references/spec.md`。要点：

- `id` = 派单的 `composition_id`；`duration` ≥ 坑位包络 + 0.3。
- `convention`：`cn` 红涨绿跌（缺省）/ `us` 绿涨红跌。**跟着片子的受众走**，别跟着数据来源走。
- `bg`：`dark` / `light` / `transparent` / `#RRGGBB`。栏目色用 `palette` 注入（`up` / `down` / `accent` / `ma` 列表……）。
- 标注的 `side`：缺省最高在上、最低在下。点在实体里（收盘价、任意价位）时，标签放在这根影线之外，引线穿过实体。
  stdout 的 `marks[].covers` 报出标签盖住了几根蜡烛：> 0 不算错，但多半该换 `side`。
- spec 落在产物旁边（如 `<工程>/mg/<composition_id>.spec.json`），日后改节奏只改 spec 重生成。

### 5. 生成 → lint → 验收

```bash
python scripts/candle_chart.py <spec.json> --out <工程>/mg/<composition_id>.html
gtrk mg lint <工程>/mg/<composition_id>.html --dispatch <工程>/split/dispatch.json
python scripts/candle_check.py <工程>/mg/<composition_id>.html --out <系统temp>/sheet.png [--video <系统temp>/preview.mp4]
```

- 产物直接写最终落点。120 根日线 + 量 + 两条均线约 5 万字符，远在 1,900,000 预算内。
- lint 的 `x-soft-alpha` 是信息项（量柱、区间带、标签底都是半透明），不用改。
- **预检不是验收**：真验收 = 真渲染引擎抽帧（`gtrk mg render` / `gtrk render`）。

### 6. 交回铺轨

派单模式交回 `/gtrk-mg`（`gtrk mg --project`），独立模式走 `gtrk mg render <html> --duration <s>` 出透明 MOV。

## 自检（脚本当场退出、不产文件）

| 查什么 | 为什么 |
|---|---|
| 某行高 < 开 / 收，或低 > 开 / 收；数不是有限数；成交量为负 | 数据本身坏了，画出来就是错图 |
| CSV 缺列；`at` / `from` / `to` / `slice` 的日期在数据里找不到 | 引用错了一根，标注会落到别处 |
| 每根 < 2.5px | 挤成一团看不清——合并周期或截取 |
| 标注 / 区间早于它指的那根长完 | 还没画出来的蜡烛没法标 |
| 标签里写的价位与那根的实际价位不符 | 凭印象写数是最常见的错 |
| 两个标注的标签叠在一起 | 叠了谁也读不清 |
| 给了 `y_range` 而标注的标签出了价格区 | 头顶空间不够（不给 `y_range` 时脚本自己留） |
| 价位线不在纵轴范围内 | 画不出来 |
| 纵轴刻度被价位标签挡得只剩 < 2 个 | 观众读不出比例 |
| 均线周期 ≥ 根数；`ma.at` 早于蜡烛长完 | 算不出 / 跟生长打架 |
| 生长或最后一个动作离颗粒末尾太近 | 没有驻留 |
| 日期标签进字幕带；版面越界 | 被字幕压住 / 出画 |
| `palette` 键拼错；产物超预算 | 静默不生效 / 静默拒挂 |

## 验收：`candle_check.py` 的读数

| 读数 | 合格线 | 量的是什么 |
|---|---|---|
| `price_err_px` | ≤ 0.6 | 用**纵轴刻度文字**（观众读到的数）拟合「价格 → 像素」，反推每根蜡烛的高开低收，与数据对账的最大偏差 |
| `ma_err_px` | ≤ 0.6 | 按收盘价**另算一遍**均线，与画出来的线逐点对账 |
| `sweep_bad` | 0 | 生长期抽 8 个时刻，「该长完没长完 / 不该出现已出现」的根次 |
| `ma_lag_px` | ≤ 一根宽 | 跟随模式下，均线笔尖与最新长完那根蜡烛中心的最大偏差（笔尖本来就在正在长的那根上，所以上限是一根宽） |
| `ma_draw` | 起笔前宽 0、描完铺满 | 单独描出模式（给了 `ma.at`）下的裁切宽度 |
| `labels[]` | 不透明度 ≥ 0.95、不出画、不进字幕带 | 每个标注 / 价位线 / 区间落下 0.8 s 后 |
| `label_overlap` | 0 | 终态标签两两相交的对数 |
| `frames` | 生长期相邻不同 | 抽样帧 sha1；终态驻留本来就静止，不算冻结 |

任一不合格退出码 1。

## 这个技法**不做**什么

- **不预测、不荐股**：没有「目标价」「买点」之类的预设标注；价位线是什么含义，由口播负责说清楚。
- **不画技术指标副图**（MACD、KDJ、RSI……）：一屏讲一件事，副图让观众找不到重点。真需要就另做一颗。
- **不做实时 / 逐笔**：数据在生成期定死，颗粒是确定性的回放。

## 硬约束（不满足别交付）

1. gsap-emit v1 全部铁律——脚本已按此发射；网格是一条合并的 path（铁律 8），蜡烛是逐元素驱动（豁免）。
2. 零卷积：没有 `filter` / `feGaussianBlur`；均线推进用 `clipPath` 的矩形宽度，不是滤镜。
3. 字体名命中渲染服务端字体表；缺省思源栈已命中。
4. 画幅 = 目标工程画幅；竖屏工程另写一份 spec（缺省版面会按画幅重排）。
5. 画面注明数据来源与口径；示例数据是合成的，MUST 在标题或文案里写明「合成数据」。
