# beat-pulse · 卡点冲击链

一个动作，三层结构：

| 层 | 做什么 | 为什么 |
|---|---|---|
| **拍点** | 把音乐的拍换算成帧号；可隔拍取、可标重拍 | 冲击必须**正好**落在那一帧——差一帧观众就觉得「没踩上」 |
| **配方** | 普通拍一套效果、重拍一套更重的；每个效果有幅度与衰减帧数 | 一首歌里每拍都满格冲击会麻木，重拍才给闪白、负片 |
| **切点** | 每拍切 / 只在重拍切 / 不切 | 「切点冲击」是 MAD 最常见的样子：换画面的同一帧打冲击 |

这一族是 MAD / 卡点视频里出现最多的手法：在一份 2095 个工程的技法图鉴里，切点震屏冲击（712 例）、胀缩呼吸卡点（431）、
切点曝光闪白（309）、RGB 色散脉冲（149）、模糊脉冲（148）、负片反色闪（128）、坏电视信号故障（130）合计两千多例。
本 skill 把它们做成参数化、确定性的一条管线，不依赖任何剪辑软件，也不套任何现成工程。

## 分工：你决定素材与轻重，脚本只做机械活

**你（agent）负责**：用哪些片段、拍点从哪来、隔几拍打一次、哪些拍是重拍、普通拍和重拍各用什么配方、在哪种拍上切。
**脚本负责**：拍点换算成帧、排段选材、逐帧算包络与变换、镜像补边、编码，以及自检。

## 工作流

### 1. 拿拍点

三种来源，spec 里三选一：

| 来源 | 什么时候用 | 写法 |
|---|---|---|
| `bpm` 网格 | 曲子速度稳定（大多数 MAD 配乐） | `{"bpm": 128, "offset": 0.35, "every": 1}`——`offset` 是第一拍在颗粒里的秒数 |
| `beats` 拍点文件 | 有拍点检测结果（任意工具，只要有 `beats` 秒数组；可选 `downbeats`） | `{"file": "beats.json", "every": 1}` |
| `hits` 秒列表 | 手工挑的几个点（鼓点、口播重音） | `[0.5, 1.25, 2.0]` |

- gtrk 目前没有单独输出拍点的命令；`gtrk audio lay --beat-align` 内部用的云端音乐分析回执里有 `beats` / `downbeats`，同格式可直接喂。
- 拍点都换算到**颗粒时间**（从这段 mp4 的第 0 帧算）：BGM 在工程里从 12.3 s 开始、这段 mp4 放在 20 s，就要把拍点减去 7.7 s（`beats.offset` 可以帮你减）。
- 相邻两拍少于 3 帧会被拒（`min_gap`）——太密的拍点打出来是一片抖，不是卡点。用 `every: 2` 隔拍取。

### 2. 定配方

三档预设（`fx`），也可以自己写 `{"normal": [...], "accent": [...]}`：

| 预设 | 普通拍 | 重拍 | 用在 |
|---|---|---|---|
| `punch`（缺省） | 推一下 + 震 | 推一下 + 重震 + 闪白 + 色散 | 燃系混剪、片头、动作戏 |
| `glitch` | 色散 + 条带错位 | 负片闪 + 重色散 + 重条带 + 震 | 赛博、故障、电子乐 |
| `breathe` | 呼吸式胀缩 + 轻放射模糊 | 呼吸 + 柔和闪白 + 模糊 | 抒情、慢歌、情绪段 |

效果参数（幅度、衰减帧数）见 `references/spec.md`。经验值：

- **衰减要短于拍间隔**：60fps、128 BPM 一拍 28 帧，衰减 8–12 帧刚好留出「回稳」；衰减拖到下一拍，画面会一直在抖，失去节奏感。
- **闪白只给重拍**：每拍都闪，观众眼睛会累，也读不出「强拍」。
- **重拍 `accent`**：`{"every": 4}` 每小节第一拍，或 `"downbeats"`（拍点文件里有 downbeats 时）。

### 3. 定切点

- `cut: "every"`：每拍换一个片段——快剪混剪。素材 ≥ 2 个，建议 ≥ 6 个，脚本会避开连续两段用同一个素材。
- `cut: "accent"`：只在重拍换，其余拍原地冲击——节奏更稳，画面能看清。
- `cut: "none"`：一个素材到底，只在拍上冲击——口播、单镜头情绪段。
- `source.lead` 跳过素材开头（很多素材头几帧是静止的）；`source.stride` 让同一素材下次出现时往后取。

### 4. 跑

```bash
python scripts/beat_pulse.py <spec.json> --out <落点.mp4>
python scripts/measure.py <落点.mp4> --spec <spec.json>
```

1080p60 约 4 秒出 1 秒（单线程 Python 逐帧）。stdout 摘要报出每个拍点的帧号、是否重拍、用了哪些效果，以及每段取材。

### 5. 进工程

产物是普通 mp4（无音轨），**放在 B-roll / 底轨之上的一条视频轨**，起点对齐坑位起点（也就是拍点换算的 0 秒）。

⚠️ `gtrk` 目前**没有命令能往工程里加任意视频 clip**。这一步是**手动**：在客户端里把 mp4 拖到目标轨、对齐起点。别为了自动化去裸手改 `.gtrk` JSON。

## 脚本的自检（任何一道不过：当场退出、不留文件）

| # | 查什么 | 为什么 |
|---|---|---|
| ① | 每段解出来**正好 n 帧** | `ffmpeg -ss` 越界时一帧不出且退出码为 0；容器时长还可能被更长的音轨撑大——实测过：视频 2 s、音轨 6 s 的素材，时长探测报 6 s，取材时只解出一半帧 |
| ② | 送进编码器的帧数 == 目标帧数 | 逐帧循环的总闸 |
| ③ | 成品帧数 == 目标帧数 | 编码器丢帧 / 补帧会让后面的拍全部错位 |
| ④ | 成品时长 == `duration`（±1 帧） | 换个维度再查一遍 |
| ⑤ | 拍点间隔 ≥ `min_gap` 帧、时长内至少一拍 | 太密 = 一片抖；拍点全在时长外 = 产物里没有一次冲击 |
| ⑥ | 素材存在、够长；要切就至少 2 个素材；配方与预设名认得 | 静默兜底只会产出「看起来没毛病、其实不对」的片子 |

产物先写成 `<落点>.part.mp4`，以上全过才改名到落点；失败时删掉半成品。

## 怎么验：`measure.py`

```bash
python scripts/measure.py out.mp4 --spec spec.json   # 验自己的：逐拍对账
python scripts/measure.py ref.mp4 --emit-hits        # 量别人的：检出切点与闪白，吐出 hits
```

| 读数 | 合格线 | 量的是什么 |
|---|---|---|
| `cut_hit` / `cut_expected` | 全中 | 每个该切的拍，最近的切点相对拍点**正好 0 帧** |
| `extra_cuts` | 0 | 不在拍点、也不在拍点效果窗口里的切点 |
| `flash_lift_median` | ≥ 8 | 闪白拍：拍点帧比**同段衰减完的参照帧**亮多少（0–255） |
| `rgb_px_median` | ≥ 2 | 色散拍：拍点帧与参照帧的 R/B 水平错位之差（px@原画幅） |
| `impact_median` | ≥ 1.3 | 震 / 推 / 条带拍：效果窗口内最动的连续 4 帧，帧间差是同段平稳帧的几倍（呼吸式胀缩的峰在拍点两翼，所以取窗口内最大） |

量法要点：切点看颜色直方图（换片段时颜色分布突变，画面自身的运动与震屏几乎不改变它）；
闪白与色散都和**同段衰减完的参照帧**比，扣掉素材本身的亮度和色边。成品是 yuv420p，色度减半采样，
色散在成片里本来就比设定值弱（设 10 px 量出 5–9 px）——读数反映的是观众看到的量。

故障注入：拿错一帧的拍点去对账，`cut_hit` 0/11，判不合格。

## 这个技法**不做**什么

- **不做转场**：两段之间是硬切，冲击就是转场。要叠化、擦除用客户端的转场。
- **不做拉镜 / 甩镜运镜**：那是 `cam-whip`（段内的镜头运动）；两者可以串着用——先 `cam-whip` 出片，再拿它当 `beat-pulse` 的素材（`cut: "none"`）。
- **不配音**：产物无音轨，BGM 在客户端里叠，起点对齐。
- **不检测拍点**：拍点由调用方给。
