# band-strobe · 横带频闪蒙太奇

一个动作，三层结构：

| 层 | 做什么 | 为什么 |
|---|---|---|
| **分带** | 画幅横切成 N 条带（缺省等分 3 条） | 同一时刻并置多个画面，信息密度是单幅的 N 倍 |
| **错相快切** | 每条带跑**自己的**素材序列，切点相位错开 | 各带不同步跳变 ⇒ 画面永远有东西在变，不会出现"整幅一起停一下" |
| **故障化** | RGB 错位 + 洗白调色 + 拖影 | 把并置的割裂感说成"信号不稳"，而不是"排版没对齐" |

典型用途是**片头 OP**：几秒钟里把整条片子的画面过一遍，观众还没看清就记住了调子。也可以当**片中闪回**（用 `rhythm` 档，节奏带顿挫）。

## 分工：你决定素材与快慢，脚本只做机械活

**你（agent）负责**：用哪些片段、几条带、多快、什么调子、多长。
**脚本负责**：排段、切片、拼带、叠带、调色、编码，以及四道自检。

这是**技法**不是模板：脚本里没有任何素材、没有栏目色板。同一份脚本给不同片子产的东西应当完全不一样——差别在你写的 spec。

## 工作流

### 1. 挑素材（这一步决定成败）

- **6–12 个片段**。少于「带数 + 1」脚本会拒绝——否则同一时刻各带避不开撞图。
- 挑**一眼能认出来**的：人物立像、标志性物件、全片最亮的一帧。0.1 秒一张，观众只来得及接收轮廓与色块，细节全是浪费。
- **片头 MUST 避开剧透**：后半程的重场（谁走了、谁回来了）留到正片。OP 是钩子不是梗概。
- 片段本身**别太静**：脚本会跳过片头（`source.lead`），但如果整段都几乎不动，快闪里会像卡住。
- 素材是**输入**，放工程目录（如 `<工程>/op/clips/`），别放 agent 自有目录。

### 2. 定节奏

两档，在 `rhythm.mode` 里选：

| 档 | 观感 | 用在 |
|---|---|---|
| `uniform`（缺省） | 全程等间隔，**一刻不停** | OP 片头。`seg: 6` = 0.1s 一张，全画幅约 30 刀/秒 |
| `rhythm` | 慢一段 → 急闪一串 → 慢一段，**有顿挫** | 片中闪回、情绪段。更"喘气"，但**容易被读成「切换时停了一下」** |

`seg` 是唯一的快慢旋钮（帧）：

| seg | 每张停留 | 观感 |
|---|---|---|
| 4 | 0.067s | 极快，接近阈下闪烁 |
| **6** | **0.1s** | **推荐起点** |
| 8 | 0.133s | 还能看清主体 |
| 12 | 0.2s | 已经不算"频闪"了 |

> 🔴 `uniform` 档下**不要**再让段长随机。等间隔的价值就是不匀速的反面；一旦随机，"停一下"的观感立刻回来。三条带的区分靠 `phase`（相位帧偏移），不靠段长。

### 3. 定带数与带高

- 缺省 `"bands": 3` = 等分。也可以给数组 `[300, 480, 300]` 指定各带高度，**合计必须等于 `height`**。
- 带数 ↑ ⇒ 信息密度 ↑、单条带的可读性 ↓。**3 条是甜点**；4 条以上每条只剩 270px，人脸就看不清了。
- 中间带加宽（如 `[300, 480, 300]`）能把视线压在中央，适合中间带放主角。

### 4. 定调色

| preset | 观感 |
|---|---|
| `warm-cyan`（缺省） | 暖高光 + 青阴影，洗白。故障片最常见的调子 |
| `wash` | 只洗白不定色向，保留原素材色温 |
| `none` | 不调色，只留频闪结构与 RGB 错位 |

- `rgb_shift`：红青错位像素数。6 轻、9 中、14 重。
- `smear`：拖影帧数。**要跟 `seg` 匹配**——一张才 6 帧时 `smear: 3` 会把相邻两张糊成一团。`seg ≤ 6` 用 2，`seg ≥ 10` 或 `rhythm` 档可以用 3。

### 5. 跑

```bash
python scripts/band_strobe.py <spec.json> --out <落点.mp4>
```

`--keep-tmp` 保留中间带文件，排查用。

### 6. 进工程

产物是普通 mp4，**放在 AI 轨/底轨之上的一条视频轨**（上面还要叠标题卡的话，标题卡走 MG 颗粒到 beat 轨，天然在视频轨之上）。

⚠️ `gtrk` 目前**没有命令能往工程里加任意视频 clip**（`ai-drama lay` 只管它自己那条轨）。所以这一步是**手动**：在客户端里把 mp4 拖到目标轨、对齐坑位起点。别为了自动化去裸手改 `.gtrk` JSON。

## 脚本的四道自检（都是踩出来的）

| # | 查什么 | 为什么 |
|---|---|---|
| ① | 每段切出来**正好 n 帧** | `ffmpeg -ss` 偏移越界时**一帧不出且退出码为 0**，整条带会静默变短 |
| ② | 拼接后帧数 == 段长之和 | 小段用 `-c copy` 拼接会在时间戳接缝丢帧 |
| ③ | 成品帧数 == 目标帧数 | 最后一道总闸 |
| ④ | 成品时长 == spec 的 `duration` | 同上，换个维度 |

任一不过就**当场退出、不产文件**。宁可炸在生成阶段，也别让一条短了 10% 的片子流到成片。

## 🩸 四个坑，每个都真机踩过

1. **取材偏移必须夹在素材长度内。** 偏移按「复用次数 × stride」递增时很容易算到素材长度之外；`ffmpeg -ss` 越界**返回空但退出码为 0**。实测整条带 218 帧变成 206/178/176，到成片才发现时长不对。脚本用 ffprobe 取真实时长再取模夹紧。
2. **用 `-frames:v N` 而不是 `-t 秒数`。** 6 帧 = 0.1s，按时长截取一取整就可能变 5 帧，几十段累计下来短一大截。
3. **选素材要排除「本带上一段」，不只是「其他带正在播的」。** 同一素材连播两段就看不出切换，等间隔也会读成"停一下"。
4. **别用 `blend=screen` 拿模糊副本抬黑位做泛光。** 它会把阴影推成品红，而故障片该是「暖高光 + 青阴影」。走 `curves` 抬黑位 + `colorbalance` 定色向。

## 这个技法**不做**什么

- **不做带内左右位移。** 参考片逐帧量过：27 个切点全是换图、零横移。"撕裂"观感纯粹来自各带内容不同，带缝本身是硬边。加位移是画蛇添足，而且会让本就割裂的画面更乱。
- **不做转场。** 带与带之间、段与段之间都是硬切。频闪的力量来自硬。
- **不配音。** 产物无音轨，音乐/音效在 NLE 里叠。

## 怎么验

抽连续帧看是不是每帧都在变：

```bash
for t in 0.20 0.30 0.40 0.50 0.60 0.70; do
  ffmpeg -y -v error -ss $t -i out.mp4 -frames:v 1 "f$t.png"
done
gtrk qc contact-sheet . -o sheet.png --cols 3
```

要量读数（切点数、错开率、段长分布），用 `scripts/measure.py`——它也能**反过来量任意一条参考片**，把别人的节奏抄成 spec 参数。
