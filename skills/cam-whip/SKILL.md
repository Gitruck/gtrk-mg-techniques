# cam-whip · 拉镜 / 甩镜卡点

三种动作，都以切点为中心、一半在出镜段一半在入镜段：

| 动作 | 出镜段（切点前 `pre`） | 入镜段（切点后 `post`） | 用在 |
|---|---|---|---|
| **甩镜 `whip`** | 加速甩向 `dir`（位移 `dist` × 画幅、转 `rot`°） | 从反方向甩入、减速落定 | 换场、换人、「下一个」——最常见的卡点换镜 |
| **拉镜 `pull`** | 急推到 `zoom` 倍（绕 `anchor` 锚点、转 `rot`°） | 从 `zoom` 倍急拉回 1 | 强调、冲击、连招（不切镜头时就是「急推急拉」） |
| **平铺推拉 `tile`** | 缩到 `min` 倍，四周露出镜像平铺 | 从 `min` 倍弹回 1 | 段落切换、「拉远看全局」的错觉 |

在一份 2095 个工程的技法图鉴里，滑移扫入换镜（180 例）、平铺推拉伪拉镜（113）、锚点拉镜连招（97）、甩镜卡点循环（92）
是运镜类出现最多的四种；本 skill 把它们做成参数化、确定性的一条管线，不依赖任何剪辑软件，也不套任何现成工程。

两个让它「像」的细节：
- **镜像补边**：甩出去、缩小时露出来的地方用画面自己的镜像填满（图鉴里的 tile / MotionTile 镜像），永远没有黑边。
- **真运动模糊**：一帧之内镜头动了多少像素，就在快门时间（缺省 0.75 帧）内按每 10 px 一个子时刻采样叠平均（≤ 12 个）。
  子采样少了会看出离散的重影——这是试出来的：固定 6 个子采样时，一帧上百像素的甩动能数出 6 个影子。

## 分工：你决定素材与动作，脚本只做机械活

**你（agent）负责**：用哪些片段、拍点从哪来、每拍用哪种动作（`moves` 轮流用）、甩多远推多深、要不要缓推和手持微震。
**脚本负责**：拍点换算成帧、查动作窗口互不重叠、排段选材、逐帧算镜头、镜像补边、运动模糊、编码，以及自检。

## 工作流

### 1. 拿拍点

与 `beat-pulse` 同口径，三选一：`bpm` 网格 / `beats` 拍点文件（`beats` 秒数组）/ `hits` 秒列表，都换算到**颗粒时间**。
每个动作要占 `pre + post` 的窗口（缺省甩镜 0.26 s、拉镜 0.36 s、平铺 0.36 s），**相邻两拍的窗口不能重叠**——
120 BPM 每拍 0.5 s 刚好放得下；更快的歌用 `every: 2` 隔拍取。

### 2. 排动作

`moves` 是一个循环列表，第 i 个拍点用 `moves[i % len]`：

```json
"moves": ["whip-left", "pull", "whip-right", "tile", "whip-up", "pull"]
```

- 字符串简写：`whip-left / right / up / down`、`pull`、`tile`；要调参就写对象 `{"type": "pull", "zoom": 2.3, "anchor": [0.65, 0.6]}`。
- **甩镜方向交替**（左、右、左……）比一直往一个方向甩更有节奏，也不容易晕。
- **拉镜转角自动左右交替**（连招才有来回感）；`anchor` 偏向画面里的主体（人脸、物体），推进去才是「推向它」。
- 一首歌里三种都用，但让甩镜占多数；平铺推拉最「重」，留给段落交界。

### 3. 定切点

- `cut: "every"`（缺省）：每个动作都换镜头——混剪。素材 ≥ 2 个，建议 ≥ 6 个，脚本避开连续两段用同一个素材。
- `cut: "none"`：一个素材到底，只在拍上做镜头动作——单镜头的「锚点拉镜连招」、口播强调。

### 4. 跑

```bash
python scripts/cam_whip.py <spec.json> --out <落点.mp4>
python scripts/measure.py <落点.mp4> --spec <spec.json>
```

1080p60 约 15 秒出 1 秒（动作窗口里的帧要做运动模糊）。stdout 摘要报出每个动作的帧窗口、做了运动模糊的帧数与最大子采样数。

### 5. 进工程

产物是普通 mp4（无音轨），放在 B-roll / 底轨之上的一条视频轨，起点对齐坑位起点。

⚠️ `gtrk` 目前**没有命令能往工程里加任意视频 clip**。这一步是**手动**：在客户端里把 mp4 拖到目标轨、对齐起点。别去裸手改 `.gtrk` JSON。

要在镜头动作上再叠冲击（闪白、色散），把本技法的产物当 `beat-pulse` 的素材（`cut: "none"`、同一套拍点）。

## 脚本的自检（任何一道不过：当场退出、不留文件）

| # | 查什么 | 为什么 |
|---|---|---|
| ① | 每段解出来正好 n 帧 | `ffmpeg -ss` 越界时一帧不出且退出码为 0 |
| ② ③ ④ | 送编帧数、成品帧数、成品时长 | 丢一帧，后面所有动作都偏离拍点 |
| ⑤ | 每个动作窗口在 [0, 总帧数) 内、相邻窗口不重叠 | 窗口重叠 = 上一个镜头还没落定下一个就甩出去，画面糊成一团 |
| ⑥ | 镜头越界不超过一圈镜像补边能覆盖的范围；`tile.min` ≥ 0.34、`pull.zoom` ≤ 4 | 再大就要铺三圈以上的镜像，补边算不过来 |
| ⑦ | 动作名、方向认得；素材存在、够长；要切就至少 2 个素材 | 静默兜底只会产出「看起来没毛病、其实不对」的片子 |

产物先写成 `<落点>.part.mp4`，以上全过才改名到落点；失败时删掉半成品。

## 怎么验：`measure.py`

| 读数 | 合格线 | 量的是什么 |
|---|---|---|
| `cut_hit` / `cut_expected` | 全中 | 每个切点正好落在拍点那一帧（颜色直方图判切点） |
| `whip_dir_ok` | 全中 | 甩镜出镜、入镜窗口里画面整体位移（相位相关）的方向与 `dir` 一致，且 > 2 px/帧 |
| `zoom_ok` | 全中 | 拉镜：出镜段逐帧缩放比 > 1、入镜段 < 1；平铺推拉相反（逐帧在 0.70–1.45 的 61 档里搜） |
| `extra_cuts` | 0 | 不在拍点、也不在动作窗口里的切点 |
| `black_edge_frames` | 0 | 画面四边出现整条纯黑带的帧（镜像补边没兜住会露黑边） |
| `blur_median` | ≤ 0.85 | 动作窗口里最快那帧的清晰度 / 同段平稳帧（拉普拉斯方差），越小模糊越重 |

示例实测：切点 8/8、甩镜方向 4/4（左甩 −74 / −96 px/帧，右甩为正，上甩 dy 为负）、推拉方向 4/4（拉镜出镜段逐帧 ×1.07、入镜段 ×0.95）、
黑边 0 帧、快动帧清晰度中位数 0.03。故障注入：拿方向与推拉都写反的 spec 去对账，0/4、0/4，判不合格。

## 这个技法**不做**什么

- **不做闪白、色散、震屏**：那是 `beat-pulse`；两者可以串着用。
- **不做 3D 空间运镜**（穿梭、绕转）：只有平面内的平移、旋转、缩放。
- **不做叠化、擦除**：两个镜头之间仍是硬切，镜头动作 + 运动模糊把硬切藏起来。
- **不配音**：产物无音轨。
